Production Safety Notice: To prevent catastrophic accidental data loss, web-based one-click overwriting of the active production database is intentionally blocked. Restorations must be executed via the authenticated CLI command with explicit confirmation.
Step-by-Step Restoration Workflow:
  1. Download / Locate Backup Archive: Obtain the target verified archive from the list below or from your external USB backup drive.
  2. Verify Archive Integrity: Click Verify Integrity below or check with certutil -hashfile <file> SHA256.
  3. Test on Staging/Test DB First: 
    python manage.py restore_database --file "filename.sql.gz" --target-db "smart_school_test" --confirm
  4. Execute Production Recovery: 
    python manage.py restore_database --file "filename.sql.gz" --confirm
External USB Physical Backup Protocol:

For total resilience against edge server motherboard/drive burnouts, export the latest archive daily to an external USB flash drive and store it in the Principal's fireproof safe:

python manage.py export_backup --file <record_id_or_name> --destination "E:\SchoolBackups"
Or use the Export to USB button on any completed backup row in the table below.
